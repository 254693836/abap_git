# ADD_ACTION001

Travelのインスタンスアクション。入力型は新規のCDS Abstract Entity
`ZLYZ210_A_ADD_ACTION001_SOL`、戻り値は `result [1] $self`。
一覧と詳細画面に `ADD_ACTION001` ボタンを公開する。

## 入出力と比較

- Travel本体の永続化された18項目を入力として受け取る。添付バイナリ、
  作成者・更新者、作成日時・更新日時、TravelIDも比較対象。
- クライアント項目MANDT、Booking明細、関連先名称、仮想項目は入力に含まない。
- 対象はアクションがバインドされたTravelID。引数のTravelIDで別の旅行を検索しない。
- SQLでアクティブDBを読み、入力構造と全項目を比較する。
  初期値も比較対象とし、変更された項目だけを比較する方式ではない。
- 不一致の場合は `failed-travel` とエラーメッセージ「この値修正しました」を返し、
  そのインスタンスの成功結果は返さない。
- DBに存在しない場合は「DBに対象の旅行が存在しません。」を返す。
- 一致時の結果はDBから取得したTravelの値。アクション内で更新・コミットは行わない。

## 画面との接続

`GetDefaultsForAddAction001` はEMLで現在のTravelを読み、全入力項目の初期値を返す。
ドラフトから呼ばれた場合はドラフトの値を使う。比較先は常にアクティブDBのため、
未保存の変更や管理日時の差異も不一致になる。新規ドラフトには通常比較先がない。

この初期値関数は入力ダイアログ用であり、画面上の値を任意のタイミングで自動送信する
独自UIコードではない。UIはアクションの入力パラメータを送信する必要がある。
このリポジトリにはフロントエンド実装がない。
Fiori elementsの初期値関数対応、およびバイナリ添付を含む全パラメータの引き渡しは
接続先のSAP/UI5環境で確認する。通常の添付アップロードUIをこのダイアログに追加した
ものではない。対応しないUIでは拡張またはODataクライアントからの明示的な送信が必要。

## SAP環境での確認

ローカルにはABAPコンパイラ・SAP実行環境がないため、以下は未実行。

1. Abstract Entity、Behavior、Behavior Pool、Projection Behavior、UI注釈を有効化する。
   `default function` 構文を接続先リリースがサポートすることを確認する。
2. Behavior PoolのABAP Unitを実行する。一致、各入力項目を個別に初期化した不一致、
   双方に同じ初期値がある場合の一致を検証する。
3. アクティブTravelで全入力をDBと一致させ、DBスナップショットが返ることを確認する。
4. Description、TravelID、金額、添付、更新日時などを変更して、不一致エラーと
   DBが変更されないことを確認する。
5. 既存ドラフト、新規ドラフト、存在しないキー、複数インスタンスで結果とメッセージを確認する。
6. ODataメタデータに18入力項目と初期値関数が公開され、画面が添付を含む値を
   欠落・丸めなしで送信できることを確認する。
